# Aeon: The Agent That Watches Itself

Most "AI agents" still want you in the loop — approve this tool call, review this diff, confirm before it sends the email. That's fine for interactive coding, but it's the wrong shape for the work most people actually want automated: morning briefs, market monitoring, PR reviews, research digests, security scans. Tasks where the whole point is that *you weren't there*. Aeon is an open-source framework built explicitly for that lane: a recurring background agent that runs on GitHub Actions, scores its own output, and patches its own skills when they break.

## A runtime, not a library

The first thing to understand about Aeon is what it isn't. It isn't a Python SDK like AutoGen or CrewAI, where you write code that orchestrates LLM calls. It isn't a visual workflow editor like n8n. It isn't a state-machine library like LangGraph. Those are tools you *build with*. Aeon is a runtime you *point at a goal and walk away from*.

Concretely, a skill in Aeon is a Markdown file. `skills/article/SKILL.md` is twenty-odd lines of instructions plus a single `var` input. The scheduler reads `aeon.yml`, matches the cron, and dispatches a GitHub Actions workflow that runs Claude Code against that skill. No Docker. No webhook server. No always-on box. If your repo is public, GitHub Actions minutes are free, which means the operational cost of running a fleet of background agents lands very close to zero. The setup floor is "clone a repo, paste a token."

## The self-healing loop

What separates Aeon from "cron job that calls an LLM" is the closed feedback loop wrapped around every run. After each skill completes, Haiku scores the output 1–5 — failed runs and empty outputs get 1, excellent outputs get 5. The score, along with flags like `api_error`, `stale_data`, or `rate_limited`, is appended to `memory/skill-health/` with a 30-run rolling history. That data feeds five meta-skills that collectively form the self-healing architecture: `heartbeat` detects stuck or chronically failing skills three times a day; `skill-health` and `skill-evals` audit quality drift and run assertion-based regression tests; `skill-repair` diagnoses and patches broken skills automatically; `self-improve` evolves prompts and config based on the performance signal.

The reactive trigger system stitches it together. Any skill can declare a condition rather than a cron — for example, `skill-repair` auto-fires whenever any skill fails three runs in a row. Most of the time none of this is visible to the operator; Heartbeat logs `HEARTBEAT_OK` and goes back to sleep. The signal only surfaces when something actually needs a human.

## Memory that survives across runs

Because every skill runs in a fresh Actions container, Aeon's memory has to live in the repo itself. `memory/MEMORY.md` is a short index, `memory/topics/` holds detailed notes by subject, `memory/logs/YYYY-MM-DD.md` is an append-only daily journal, and `memory/issues/` is a tiny issue tracker that the health skills file into and the repair skills close. The whole thing is version-controlled — you can `git log memory/` and see exactly what the agent learned, when, and why. There is no vector database, no hosted memory provider, no separate state service. The agent's history is the diff history.

## A fleet, not a single instance

Aeon also spawns copies of itself. The `spawn-instance` and `fork-fleet` skills can fork the repo, select a subset of relevant skills, and register the new instance in `memory/instances.json` — one for crypto monitoring, another for research, another for whatever specialization you want. The weekly `fork-skill-digest` aggregates what other operators have enabled across the active fork network, and surfaces "default flip" candidates when multiple forks independently override the same upstream default. The fleet teaches upstream which defaults are wrong. As of the latest leaderboard, the most-customized fork runs 94 of the 121 shipped skills; the median fork runs just `heartbeat`, treating the framework as pure infrastructure they extend with their own custom skills.

## When to reach for it

Aeon is not a better choice than Claude Code for writing code interactively, and it's not trying to be. It's a better choice when the work is genuinely recurring, the operator wants to be notified rather than asked, and the failure mode of *the agent breaking silently for a week* is unacceptable. That last constraint is the one that drives every architectural decision — the scoring, the heartbeat, the reactive triggers, the version-controlled memory. The point of an autonomous agent isn't the autonomy itself; it's the trust that lets you stop watching.
