# Aeon: The Agent You Don't Watch

Most AI agent tools were built around a human in the loop. You type, it proposes, you approve, it acts. That model works when you're sitting at a keyboard. It collapses the moment you walk away. Aeon, an open-source framework that runs Claude Code on GitHub Actions, is built for the inverse case: tasks that should happen whether or not anyone is watching.

## The unattended agent

The pitch is simple. Aeon ships as a repository you fork. Inside it lives `aeon.yml`, a YAML file that maps cron schedules to skills — small markdown prompt files in `skills/`. Configure once, push, and GitHub Actions becomes the runtime. A morning brief at 7 AM UTC, a token-price check every 30 minutes, a PR review at 9, a research digest at 14:00. The agent never asks for approval. It runs, writes results to `memory/`, sends a notification to Telegram, Discord, or Slack, and goes back to sleep.

That design choice — no interactive loop — is what separates Aeon from tools like Claude Code (interactive coding sessions) or n8n (workflow orchestration without LLM reasoning). The repository now ships with 121 skills across six categories: research and content, dev and code, crypto and markets, social and writing, productivity, and meta/agent maintenance. Every skill is a single markdown file. There is no SDK to learn, no orchestrator to install. The prompt is the program.

## Self-healing as a primitive

The harder problem with unattended agents is not getting them to run. It's keeping them running. APIs change. Rate limits trip. A skill that worked last week starts returning empty output. If a human isn't checking, broken skills stay broken.

Aeon's answer is a closed-loop maintenance system baked into the framework. Every skill output gets scored 1–5 by Haiku after each run. Scores land in `memory/skill-health/` with a rolling 30-run history, alongside flags like `api_error`, `stale_data`, and `rate_limited`. A skill called `heartbeat` runs three times a day, scans `memory/cron-state.json` for failed or stuck skills, and decides whether to bother the operator. Nothing wrong? It logs `HEARTBEAT_OK` and stays silent.

When something does break, `skill-repair` takes over. It reads the failing skill's recent logs, diagnoses the cause, and patches the prompt or workflow. Reactive triggers in `aeon.yml` declare the policy directly:

```yaml
reactive:
  skill-repair:
    trigger:
      - { on: "*", when: "consecutive_failures >= 3" }
```

The system also tracks itself economically. Every run appends token usage to `memory/token-usage.csv`, and `cost-report` produces a weekly per-skill breakdown.

## Memory that survives runs

Each GitHub Actions invocation is a fresh container. The agent has no memory of yesterday's run unless it writes it down. Aeon makes this explicit. `memory/MEMORY.md` is the index — the agent reads it first and writes to it last. Topic-specific notes live in `memory/topics/`. Daily logs go in `memory/logs/YYYY-MM-DD.md`. Issues with skills get structured tracking in `memory/issues/` with a YAML-frontmatter lifecycle: open → investigating → fixing → resolved.

The pattern is older than LLMs — it's how Unix shell scripts have always passed state across invocations — but it works because the agent is forced to be deliberate about what crosses the boundary between runs.

## Identity is optional

A neat detail: Aeon has no personality by default. To make it write in your voice, you drop files into `soul/` — `SOUL.md` for identity, `STYLE.md` for tone, examples and raw data for calibration. Every skill that produces output (articles, tweets, digests) reads these first. Leave them empty and you get neutral prose. Fill them in and the framework writes as you.

## Why this matters

The agent ecosystem is crowded with frameworks that demonstrate well in a demo and fall over in production. The interesting question isn't whether an agent can complete a task — most can, eventually, with handholding. The question is whether it can run for months without you, recover when things break, and not silently degrade into a Markov chain of empty outputs.

Aeon is a bet that the answer is: yes, if you make scheduling, memory, scoring, and self-repair first-class primitives of the framework rather than features bolted onto a chat loop. Whether the bet pays off depends on how well the self-healing loop actually closes in the wild. The instrumentation is there. The next year will reveal whether the agent stays alive.
